# Project Epoch 전면 감사

감사 기준일: 2026-07-31

작업 브랜치: codex/strategic-game-upgrade

## 1. 감사 방법과 판정 표기

이 문서는 저장소 전체 구조, 실제 진입점, 데이터, 테스트, 지도 생성물, 자산, 문서 및 Git 상태를 읽고 Godot 4.7.1로 직접 파싱·부팅·헤드리스 테스트한 결과다.

- **확인됨**: 코드, 데이터, 명령 출력 또는 저장소 산출물로 직접 확인했다.
- **추정**: 정적 구조상 위험이 높지만 실제 그래픽 창, 프레임 프로파일러 또는 장시간 플레이로 아직 재현하지 못했다.
- **미검증**: 출시 판정에 필요하지만 감사 시점에 해당 증거가 없다.

기존 변경은 되돌리지 않았다. 감사 시작 시 추적 파일 11개가 수정되어 있었고 Godot 실행 파일, import 메타데이터와 uid 파일이 다수 미추적 상태였다. 타일 자원, 임의 개척 위치, 개척자, 추가 도시, 군주 이름, 좌클릭 지도 이동 및 통치 버튼 배치 변경은 보존 대상이다. project.godot의 Godot 4.7 feature 및 텍스처 필터 차이도 출처를 단정하지 않고 보존한다.

## 2. 현재 기술 스택과 실행 방법

### 확인됨

- 엔진: Godot 4.7.1 Standard, GDScript.
- 렌더러: GL Compatibility.
- 실제 진입점: project.godot → res://src/main.tscn → res://src/main.gd.
- package.json, C# 프로젝트, GDExtension은 없다.
- export_presets.cfg가 없어 출시 빌드 프리셋은 없다.
- 루트 index.html은 게임이 아니라 설계 문서 리디렉션이다.
- 저장소 안의 로컬 콘솔 실행기는 Godot_v4.7.1-stable_win64_console.exe다.

현재 개발 실행:

~~~powershell
Godot_v4.7.1-stable_win64.exe --path .
~~~

현재 파싱 확인:

~~~powershell
Godot_v4.7.1-stable_win64_console.exe --headless --editor --path . --quit
~~~

감사 시 메인 장면 20프레임 headless 부팅은 종료 코드 0, 약 1.03초였다. 별도 감사 실행에서는 프로젝트 import·parse 약 4.2초, 메인 부팅 약 1.8초가 측정됐다. 장비·캐시 상태가 달라 이 수치는 기준선이며 출시 성능 판정은 아니다.

## 6. 현재 실제 플레이 가능 범위

### 확인됨

헤드리스 UI 스모크는 새 게임부터 첫 도시 건설, 첫 시설 완공, 정착민 선택, 도시 관리, 개척자 생산, 두 번째 도시 건설, 명령 큐, 외교, 턴 종료와 불러오기까지 통과한다. 코어 테스트는 모집·이동·전투·전쟁·평화·AI·저장 왕복을 검증한다.

### 미검증

- 실제 그래픽 창에서 사람이 처음부터 끝까지 수행한 최신 E2E 기록.
- 실제 클릭으로 군대 선택 → 공격 → 전투 보고 → 후퇴 또는 점령까지의 흐름.
- 저장 후 프로세스를 완전히 종료·재실행한 복원.
- 1024 미만 및 모바일 유사 폭에서의 전체 플레이.
- 출시 export 산출물.

따라서 현재 상태는 기능이 넓은 프로토타입이지만 출시 가능한 버티컬 슬라이스로 판정할 수 없다.

## 7. 치명적 구조 문제

### P0: 권위 상태가 세 갈래로 분리됨

1. GameState는 국가·프로빈스·군대·외교를 소유한다.
2. F5 도시·타일·가구·시설은 main.gd가 소유한 TileTerritoryManager에 있고 GameState.metadata.project_epoch_campaign으로 중첩 저장된다.
3. 더 풍부한 72지역 WorldSession은 도시 성장·건설·도로·보급을 갖지만 데모와 테스트 전용이다.
4. GovernanceSession도 독립 상태이며 일부 값만 코어로 되돌린다.

결과적으로 도시 생산이 국가 국고·군대 보급·외교·AI와 하나의 턴 경제로 연결되지 않는다. GameSession 중심의 단일 권위 저장 구조가 필요하다.

### P0: UI와 명령 계약 불일치

- UI가 노출하는 move_capital, occupation 및 일부 외교 행동을 mapper가 지원하지 않는다.
- 외교 UI 9개 행동 중 모욕, 불가침, 통행권, 독립 등은 실제 명령으로 변환되지 않는다.
- 동맹·불가침·휴전 표시는 일부 고정 문자열이며 presenter가 treaties를 내보내지 않는다.
- 외교 비용과 수락 확률은 표시되지만 실제 차감·상대 판단이 없다.
- 종속 요구는 상대 수락 없이 즉시 종속 조약을 만든다.
- 평화의 독립 승인 조건은 전달되지만 처리되지 않는다.

출시 UI에는 실제로 작동하는 행동만 노출하고, 모든 버튼을 동일한 검증·비용·결과 계약에 연결해야 한다.

### P0: 군사 규칙의 구멍

- 공격 검증이 전쟁 상태를 확인하지 않아 중립국 공격이 가능하다.
- UI가 보내는 이동 병력량과 주둔 잔여량을 코어가 무시한다.
- presenter는 여러 군대를 프로빈스 병력 숫자 하나로 합쳐 편제와 개별 군대 선택을 잃는다.
- 편제 units가 있는 군대 모집은 soldiers만 늘려 실제 전투력과 불일치할 수 있다.
- 보급·피로·공성 함수가 TurnProcessor에 연결되지 않았다.
- 풍부한 전투 결과가 UI에서는 단계 완료 건수로 축약된다.

### P0: 같은 턴 자원 초과 사용

TurnProcessor는 모든 명령을 동일한 사전 상태로 먼저 검증하고 나중에 실행한다. 같은 국고를 쓰는 개발 명령 여러 개가 모두 통과해 실행 후 국고가 음수가 될 수 있다. 실행 직전 재검증 또는 명령 예약이 필요하다.

### P0: 도시 경제가 턴 경제와 분리됨

- 타일 생산량은 UI에 보이지만 턴당 비축으로 적립되지 않는다.
- 시설 유지비가 실제로 차감되지 않는다.
- 추가 도시는 건설되지만 상세 관리가 첫 도시만 허용한다.
- 추가 도시 성장·식량·생산 진행이 없다.

## 8. 지도 감사

### 유지 가치가 높은 부분

- 실제 해안선, LCC 투영, 오프라인 바이너리, source hash와 라이선스 문서.
- 307,200 Dictionary를 만들지 않고 두 byte array로 유지.
- overview LOD, 가시 청크 선택, mode/chunk 텍스처 캐시.
- 실제 좌표 도시와 screen-space 텍스트.
- 텍스트 충돌 억제.

### 치명적 문제

- 생성 매니페스트의 river와 wetland 타일 수가 모두 0이다.
- 내륙 지형은 실제 고도·하천·토지피복이 아니라 경위도 사각 범위와 noise 휴리스틱이다.
- 한반도 산맥, 압록강·두만강·한강 및 중국 동부 주요 하천과 평야가 전략 규칙으로 재현되지 않는다.
- 13개 프로빈스 anchor를 제한된 띠 안에서 최근접 배정하므로 넓은 월드맵의 정치 밀도가 낮고 경계가 자연 지형을 따르지 않는다.
- world-map 렌더 경로는 상시 국가·프로빈스 경계를 별도 계층으로 그리지 않는다.
- 16×16 청크 텍스처를 확대하므로 고배율에서 블록화된다.
- 기존 city_selected 신호는 메인에 연결되지 않아 지도 도시 클릭이 장식에 가깝다.
- 현대 도시명 name을 우선 표시하고 nameHistorical을 활용하지 않는다.

## 9. UI·UX·접근성 감사

### 확인됨

- 기본 테마는 버튼 normal, hover, pressed, focus를 일부 제공한다.
- 툴팁 화면 경계 clamp가 있다.
- 지도는 마우스 드래그·휠 조작을 지원한다.

### 문제

- 게임 화면은 좌 230, 우 330, 하단 188인 고정 3열 구조다.
- _on_resize는 국가 선택과 첫 교지만 다루며 게임 화면을 접거나 drawer로 바꾸지 않는다.
- 주요 창은 720~860 최소 폭, 610~650 높이여서 작은 화면에서 잘린다.
- city detail Window가 exclusive가 아니어서 배경 입력 누출 위험이 있다.
- 지도 키보드 입력은 Home과 개발용 F6~F9뿐이다.
- 일부 타일 버튼은 FOCUS_NONE이다.
- 색만으로 관계·전쟁·소유를 구분하는 경우가 있다.
- disabled 스타일, OptionButton, CheckBox, Window, Scrollbar, 탭 hover/focus 상태 체계가 불완전하다.
- 한국어 제품 안에 Province, Governor, AI Assistant, Task Queue 및 faux-Latin 빌드 문구가 혼재한다.
- 저장소에 폰트 파일이 없고 지도는 OS fallback font를 직접 사용한다.
- 일부 지도 텍스트의 정적 대비는 낮다.
- 초상과 군주 프로필은 고구려·백제·신라 3개만 있어 나머지 플레이 세력은 빈 프로필이다.

### 추정

- 툴팁은 show 직후 이전 프레임 size를 clamp에 사용할 가능성이 있다.
- 고정 폭 구조는 1024 미만에서 핵심 지도를 심하게 가릴 가능성이 높다.

두 항목은 최신 실제 창 캡처와 입력 테스트로 확인해야 한다.

## 10. 자산 감사

### 확인됨

- 도시 6종 PNG는 서로 일관된 3/4 시점과 투명 배경을 갖춰 보존 가치가 있다.
- 같은 이름 SVG는 진짜 경량 벡터가 아니라 1536×1024 PNG를 base64로 넣은 4.19~4.79MB 래퍼다.
- PNG도 각각 약 3.1~3.6MB라 동일 장면이 중복 저장된다.
- 런타임은 이 대형 SVG 6개를 시작 시 모두 로드한다.
- SVG width/height 160×120과 viewBox 1536×1024가 handoff 문서 계약과 맞지 않는다.
- PNG에 C2PA/OpenAI 생성 메타데이터가 있지만 자산 출처·권리·수정 이력 문서가 없다.
- 도시 관리 아이콘 4종은 같은 32×32, 2.2px 선 스타일이라 일관성은 있다.
- 전체 UI에는 통합 아이콘 체계가 없다.

라이선스 출처가 분명한 Natural Earth 외의 생성 자산은 provenance 문서를 추가해야 한다. 상용 게임 자산은 포함하지 않는다는 기존 고지는 유지한다.

## 11. 저장·불러오기 감사

### 확인됨

- 코어 저장 schema 2와 v0→v1→v2 마이그레이션.
- 개척 캠페인 schema 4.
- 타일 영토 state version 10.
- governance version 1.
- 미연결 world save version 2.
- JSON이 Dictionary가 아니면 코어 저장은 안전하게 실패한다.
- 코어+통치 및 타일 캠페인 왕복 테스트가 있다.

### 문제

- 최종 파일에 직접 쓰며 임시 파일, 원자 교체, 백업이 없다.
- 필드별 의미 검증이 약하다.
- 공용 user://autosave.json을 쓰는 UI 테스트가 있어 한 차례 실행 순서 의존 실패가 재현됐다.
- 불러오기 때 presentation 명령은 지우지만 core queue는 복원해 보이지 않는 예약 명령이 실행될 수 있다.
- 다섯 버전 체계의 통합 마이그레이션 전략이 없다.
- 손상 필드, 미래 버전, 실제 프로세스 재시작 복원 테스트가 부족하다.

## 12. AI 및 게임 디자인 감사

### 확인됨

- AI는 경제·군사·외교·평화 planner로 분리되어 있다.
- 군사 planner는 이유 코드를 만들고 100턴 불변식 테스트가 있다.

### 문제

- 평가는 병력, 국고, 인력, 안정, 전쟁 피로, 인접 적과 지역 수에 제한된다.
- 도시 성장, 자원 부족, 방어 취약, 보급, 종속 충성, 장기 목표를 충분히 평가하지 않는다.
- AI profile 데이터가 실제 scenario metadata에 적재되지 않아 외교 AI가 기본값을 자주 쓴다.
- 판단 이유가 UI와 저장 스냅샷으로 전달되지 않는다.
- 도시·타일·거버넌스가 코어와 분리되어 AI가 플레이어와 같은 경제 규칙을 쓰지 않는다.

## 13. 성능 감사

### 확인됨

- data와 assets는 약 62.11MB.
- Natural Earth 원본 GeoJSON 약 14.5MB.
- 도시 SVG와 PNG 중복이 assets 대부분을 차지한다.
- 스냅샷은 Gateway, 메인, 지도에서 여러 번 deep copy된다.
- snapshot 갱신 시 지도 공간 인덱스와 청크 캐시를 다시 만든다.
- map mode별 chunk cache eviction이 없다.
- resource mode와 선택 강조는 가시 타일을 매 redraw 순회한다.
- 마우스 drag motion마다 redraw한다.

### 미검증

- 실제 FPS와 프레임 시간.
- 캐시 최대 메모리.
- 장시간 메모리 증가.
- 도시·군대 수 증가 시 성능.

기존 테스트는 전체 30만 타일을 매 프레임 그리지 않는다는 구조만 검증한다. 성능 개선 완료 선언 전 실제 계측이 필요하다.

## 18. 감사 결론

Project Epoch는 단순 목업이 아니다. 지도, 도시 타일, 군사, 통치, 외교와 테스트에 상당한 실제 구현이 있다. 그러나 현재는 각 구현이 서로 다른 권위 상태에 걸쳐 있고 일부 UI가 작동하지 않는 명령을 약속한다. 가장 가치 있는 업그레이드는 기능 수를 늘리는 것이 아니라 도시–국가경제–군대–외교–AI를 하나의 턴과 저장 상태로 연결하고, 그 흐름을 실제 화면에서 읽고 조작할 수 있게 만드는 것이다.

출시 가능한 버티컬 슬라이스 판정은 아직 보류한다.
