# Project Epoch 버티컬 슬라이스 업그레이드 계획

기준: docs/CODEX_AUDIT.md  
원칙: 기존 작동 기능과 데이터를 보존하고, 각 체크포인트마다 파싱·테스트·실행·화면 검증 후 로컬 커밋한다. 원격 push는 하지 않는다.

## 완료 판정 규칙

- 코드를 추가했다는 사실만으로 체크하지 않는다.
- 각 항목은 플레이 결과, 상태 변화, 명령 출력 또는 캡처 증거가 있어야 한다.
- 기존 테스트를 삭제하거나 assertion을 약화해 통과시키지 않는다.
- 새 시스템은 활성 F5 경로에 연결되어야 한다.
- 추정 성능 개선은 실제 frame time 또는 메모리 측정 전 완료로 쓰지 않는다.

## CP0. 감사와 안전 기준선

목표:

- 기존 변경을 보존할 전용 브랜치.
- 저장소·실행·데이터·자산·테스트 감사 문서.
- 전체 테스트 목록과 회귀 기준.

완료 기준:

- codex/strategic-game-upgrade 브랜치.
- CODEX_AUDIT, CODEX_UPGRADE_PLAN, CODEX_UPGRADE_LOG 존재.
- 기존 12개 러너의 결과 기록.
- 기존 dirty 파일과 생성 파일 분리.

## CP1. 실행·테스트·저장 안정화

구현:

- Godot 4.7.1 기준 tools/run_all_tests.ps1 정비.
- 모든 활성 러너 포함 및 테스트별 save path 격리.
- CI의 삭제된 러너와 4.6.3 불일치 수정.
- .gitignore에 로컬 실행기, uid/import 산출물 정책 반영.
- readable boundary 자원 누수와 공용 autosave 플래키 제거.
- atomic save, backup, 미래 버전 및 손상 필드 안전 실패.
- Windows export preset과 개발 export 검증.

검증:

- 로컬 전체 테스트 한 명령.
- CI 명령과 동일한 headless 파싱.
- 손상·구버전·미래 버전 저장 테스트.
- export 산출물 실행 또는 최소 headless 부팅.

## CP2. 활성 상태 모델과 명령 계약 정리

구현:

- GameSession이 캠페인 도시·타일·통치 상태를 저장하는 명시적 필드와 facade.
- metadata에 숨어 있는 상태를 버전 관리되는 campaign state로 정규화.
- 기존 schema 2 및 campaign schema 4 마이그레이션 유지.
- presentation snapshot에 treaties, 개별 armies, 최근 battle reports, AI reasons 추가.
- 미지원 UI 행동은 우선 disabled+이유 표시, 구현 뒤 활성화.
- 같은 턴 자원 예약 또는 실행 직전 재검증.

검증:

- 기존 저장 불러오기.
- 명령 여러 개의 국고 초과 사용 방지.
- 보이지 않는 core queue가 load 후 실행되지 않음.
- UI 버튼 수와 실제 mapper 지원 명령 일치.

## CP3. 도시·영토·자원·건설 핵심 루프

구현:

- 모든 도시를 동일 모델로 관리.
- 식량, 목재, 석재, 철, 재정, 인구/병력 자원의 턴 생산·소비.
- 지형·타일 자원·가구·시설·도로가 생산에 반영.
- 시설 유지비, 식량 소비, 인구 성장/감소, 치안·문화·방어·주둔군.
- 도시 건물 슬롯과 역할 선택.
- 수도/변방, 연결/고립, 행정 비용과 보급.
- 추가 도시 상세 관리와 도시 목록.
- 결과 예측과 변화 원인 breakdown.

버티컬 슬라이스 플레이:

첫 도시 개척 → 자원 확인 → 첫 건설 → 가구 배치 → 3턴 생산 → 개척자 → 두 번째 도시 → 연결/행정 비용 → 성장.

## CP4. 군대·이동·전투·공성

구현:

- 개별 군단 선택과 편제.
- 보병·창병·궁병·기병·공성 병기 모집.
- 병력 일부 이동 및 주둔군 유지.
- 전쟁 상태 없는 공격 거부.
- 지형 이동비, 강 도하, 보급, 피로.
- 보급망 및 공성 턴 처리 연결.
- 전투 결과 보고: 양측, 손실, 보정, 승패 이유, 점령, 포로, 사기, 후퇴.
- 지도 이동·충돌·피해·퇴각 피드백.

버티컬 슬라이스 플레이:

병종 모집 → 인접 이동 → 전쟁 선언 → 강/산악 전투 → 성벽 공성 → 전투 보고 → 점령 또는 후퇴.

## CP5. 외교·정통성·종속국·통치

구현:

- 중립, 우호, 동맹, 불가침, 적대, 전쟁, 조공, 종속, 휴전 상태.
- 실제 비용·조건·AI 수락·실패 이유.
- 무명분 전쟁의 정통성·민심·주변국 경계·반란 위험.
- 종속국 충성, 조공, 병력 의무, 지연/거부, 독립.
- 거버넌스 개혁과 코어 정부·국고·행정·반란의 양방향 연결.
- 동일 기능 계층의 신앙/제사 유형과 지역 서사.

검증:

- 관계 상태가 AI·전쟁·경제 또는 반란에 실제 영향.
- 종속 요구는 즉시 성공하지 않고 수락 판정을 거침.
- 무명분 전쟁 페널티 저장·복원.

## CP6. 국가 AI

구현:

- 위협, 국경, 자원 부족, 도시 성장, 방어 취약, 보급, 전쟁 피로, 종속 충성, 장기 목표 평가.
- 국가 성향과 현재 상황 분리.
- 플레이어와 같은 비용·보급·외교 규칙 사용.
- 개발 모드 AI 이유 패널과 저장 가능한 reason record.

검증:

- 공격적 AI도 보급 붕괴 시 전쟁을 피함.
- 수도 위협 시 방어 집중.
- 경제 성향이 도시 성장과 연결망 우선.
- 100턴 simulation 불변식과 행동 다양성.

## CP7. 전략 지도

구현:

- 기존 Natural Earth 해안선과 오프라인 파이프라인 유지.
- 주요 강과 전략 평야·산맥의 명시적 데이터 레이어.
- river/wetland 타일과 이동·방어·성장·보급 효과.
- 13개 기존 핵심 지역 보존 + 버티컬 슬라이스 밀도에 맞는 전략 지역 확장.
- world-map 국가/프로빈스 경계 mask와 타일 경계의 시각 계층 분리.
- 역사명 우선 LOD와 불확실성 주석.
- 도시 marker 클릭 연결.
- 고배율 블록화를 줄이는 LOD/경계 표현.
- cache eviction 및 redraw 계측.

검증:

- 압록강·두만강·한강·낙동강과 중국 동부 주요 수계가 식별됨.
- 한반도·요동·산둥·규슈·혼슈 상대 위치 육안 확인.
- pan/zoom frame time 기록.
- label collision과 줌 중요도 테스트.

## CP8. UI·UX·역사적 시각 디자인

구현:

- 먹, 닥종이, 목재, 청동, 철, 석재에서 가져온 절제된 토큰.
- 상단 자원 바, 지도 툴팁, 도시·군대·외교·전투·건설·저장 UI의 정보 계층 통일.
- SaaS/개발자 용어와 faux-Latin 문구 정리.
- hover, pressed, disabled, focus 전 상태.
- 통합 아이콘 체계.
- CJK font 및 지도 텍스트 outline/contrast.
- 1024 이하에서 좌우 패널 drawer, 좁은 화면 bottom sheet.
- modal exclusive, Esc, focus 이동, 배경 입력 차단.
- 색상+패턴/아이콘의 이중 구분.

검증:

- 1920×1080, 1280×720, 1024×576, 768×720, 480×800 캡처.
- 겹침, 잘림, 빈 아이콘, focus, modal 입력 테스트.
- 최신 캡처를 docs/ui/captures/upgrade에 보관.

- 자산 provenance와 라이선스 문서.

검증:

- data/assets 크기 전후 비교.
- 초기 부팅 시간.
- 지도 pan/zoom frame time.
- 장시간 객체/RID 누수.
- 도시·군대 증가 stress test.
